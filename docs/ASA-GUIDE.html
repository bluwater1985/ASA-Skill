这是什么

ASA 是一个工程管理流程引擎，同时支持 Claude Code 和 Gemini CLI 两个 AI 客户端。它把需求、架构、任务以结构化 YAML 节点管理，驱动 AI 按「需求澄清 → 影响分析 → 变更传播 → 编译 → 验证」的闭环工作，而不是让 AI 直接拍脑袋写代码。

核心主张：

  • 需求驱动 — 先聊清楚需求，再写代码
  • 全链路变更管理 — 改一个需求，自动分析影响并传播到下游
  • 状态机约束 — 节点生命周期合法演进，非法跳转拒绝
  • CI 门禁 — validate 兜底，防止 docs/节点漂移与未完成传播

模块职责

commands/（命令层）

加载数据 → 处理 → 写回 → 输出。每个命令独立文件，行为可测。

lib/（库层）

无状态工具：YAML 解析、matrix 读写、图遍历、状态机校验、changelog。

hooks/（防御层）

独立脚本，Claude(argv) 与 Gemini(stdin) 双协议，拦截/放行输出明确标记。

YAML 解析器设计

零外部依赖意味着要自制 YAML 解析器。它支持：

嵌套结构

标量 / 对象 / 数组 / 多键对象数组 / 深层嵌套

flow 集合

`[...]` / `{...}` 含嵌套与引号内逗号

安全转义

反斜杠、引号、换行、Tab 正确 round-trip

内联注释

仅引号外、`#` 前有空白才算注释

显式报错

Tab 缩进、块标量、未闭合引号/括号

引号保护

冒号/首尾空白/flow 形态字符串自动加引号

节点状态机

REQ 需求

proposed → approved → implemented → deprecated
     ↓                 ↓
rejected         modified
  ↺ 可重新提交
deprecated 吸收态

ARCH 架构

draft → reviewed → approved → superseded
  ↺                    ↓
draft 修订重开    superseded 吸收态

TASK 任务

pending → in_progress → completed → verified
   ↑          ↓
cancelled    blocked → in_progress
  ↺ 误取消可恢复
非法跳转直接拒绝（如 pending → verified）。状态变更自动记录到 changeLog 并递增版本。

一致性保障

机制作用触发
docs digestdocs/ 内容 SHA-256（含文件名），检测篡改/未编译validate / patch
nodes digestnodes/ 内容 SHA-256（CRLF 归一化），检测节点↔docs 漂移validate
reconcile从 nodes 重建摘要，修复不一致；matrix 缺失自举启动序列 / 手动
atomic write先写 `.tmp` 再 rename，防半写损坏所有写盘

从零到第一个需求

# 1. 在项目里初始化 ASA（Claude 与 Gemini 体验一致，都输入 /asa init）

# 2. 添加需求、架构、任务
node .asa/index.js add-req "规则检查引擎" --priority P1
node .asa/index.js add-arch "规则引擎架构"
node .asa/index.js add-task "实现原子函数"

# 3. 建立依赖关系
node .asa/index.js edge add REQ-001 ARCH-001 --type depends
node .asa/index.js edge add ARCH-001 TASK-001 --type refines

# 4. 推进状态 + 进入实现阶段
node .asa/index.js status REQ-001 approved
node .asa/index.js set phase implementation
node .asa/index.js set active-task TASK-001

# 5. 让 AI 实现代码（hook 保证"做完一个再下一个"）

# 6. 事务闭环
node .asa/index.js compile
node .asa/index.js validate   # 应输出 ✅ 健康检查通过

当需求变更时，ASA 的传播链让下游节点自动联动：

追加产出

CI 门禁通过
幂等机制：每个动作先检查目标是否已满足，已满足则跳过；失败动作保留为 partial，重跑继续，不丢意图。

CI 门禁（validate）

检查项失败时
docs digest 与期望一致❌ docs/ 已被篡改或未运行 compile
nodes digest 与 matrix 一致❌ 节点文件已变更但未重新 compile
无未完成传播条目❌ 存在未完成的变更传播
任务文件存在❌ 索引任务指向的文件不存在

↓ compile

写命令同时更新 nodes 与 matrix 摘要，compile 刷新 docs 与 digest。validate 用 docs digest + nodes digest 双校验保证一致性。

Hook 双协议

Claude Code（argv）

node .asa/hooks/check-work-order.js "$FILE_PATH"

hook 通过 process.argv[2] 拿到目标文件路径。若为 $FILE_PATH 未展开（字面量）则回退到 stdin JSON 解析。

Gemini CLI（stdin JSON）

{"tool_input":{"file_path":"/abs/path"}}

hook 解析 stdin JSON，从多个候选键提取文件路径。提取不到时 fail-open 放行。

拦截/放行输出明确标记：[ASA 拦截] 表示 hook 主动拒绝，[ASA 放行] 表示通过——让用户能区分「拦截生效」与「hook 报错」。

中断与恢复

场景机制
propagate 中断条目标记 partial，重跑按幂等检查跳过已完成动作，继续未完成
失败动作（非法转换/缺字段）保留条目不丢弃，返回非零退出码，validate 持续阻塞直到解决
matrix 损坏/缺失reconcile 用骨架自举重建（edges 需备份）
写盘中断atomic write（.tmp → rename）防半写

FAQ 与排障

常见问题

Q: validate 报「docs/ 已被篡改」

运行 node .asa/index.js compile 后重新 validate。

Q: validate 报「节点文件已变更但未重新 compile」

节点被直接编辑未走命令。运行 compile 同步 docs 与 nodesDigest。

Q: hook 拦截「没有活跃 Task」

在 implementation/review 阶段需先激活任务：node .asa/index.js set active-task TASK-001。

Q: matrix.yaml 损坏了怎么办

备份后运行 node .asa/index.js reconcile 自举重建（edges 需从备份恢复）。

Q: 节点文件含 Tab 缩进报错

ASA 的 YAML 不允许 Tab 缩进。改用空格，或用 validate-yaml hook 定位。

Q: hook 无输出/不拦截

检查 settings.json 的 hook 配置；路径含空格时需加引号。
